Bash essenziale per il metabarcoding

Una lezione pratica di 60 minuti per chi parte da zero

Terminale, percorsi, organizzazione dei file, controllo dei FASTQ compressi, pipe, log e ambienti Conda.

Bash non è una lista di comandi da imparare a memoria. È un modo preciso e riproducibile per dire al computer dove sono i dati, quale programma deve usarli e dove devono finire i risultati.

Questa lezione dura circa 60 minuti ed è pensata per chi non ha mai usato un terminale. Lavoreremo su un piccolo progetto di esempio con file FASTQ compressi, organizzato come un’analisi reale.

Obiettivi della lezione

Alla fine della lezione sarai in grado di:

  • riconoscere terminale, shell, prompt, comando, opzione e argomento;
  • orientarti nel filesystem con pwd, ls e cd;
  • creare e organizzare cartelle con mkdir, cp e mv;
  • ispezionare file di testo e file FASTQ.gz senza aprirli interamente;
  • selezionare più file con i wildcard e collegare comandi con una pipe;
  • salvare output e messaggi di errore in un log;
  • attivare l’ambiente Conda del corso e trovare l’help di un programma.

0. Preparare il progetto di esercitazione

Questa preparazione richiede circa un minuto e può essere eseguita dal docente prima della lezione. Copia e incolla l’intero blocco seguente. Crea un progetto nella tua home Linux e quattro piccoli FASTQ compressi. Non è necessario comprendere ora ogni carattere del blocco: i costrutti utilizzati verranno incontrati durante la lezione.

mkdir -p "$HOME/microbiome-bash-lab"/{input,metadata,output,logs,notes}
cd "$HOME/microbiome-bash-lab"

printf '@sample_A_read_1/1\nACGTACGTACGT\n+\nIIIIIIIIIIII\n@sample_A_read_2/1\nTGCATGCATGCA\n+\nIIIIIIIIIIII\n' \
  | gzip > input/sample_A_R1.fastq.gz

printf '@sample_A_read_1/2\nTACGTACGTACG\n+\nIIIIIIIIIIII\n@sample_A_read_2/2\nCATGCATGCATG\n+\nIIIIIIIIIIII\n' \
  | gzip > input/sample_A_R2.fastq.gz

printf '@sample_B_read_1/1\nAAAACCCCGGGG\n+\nIIIIIIIIIIII\n@sample_B_read_2/1\nTTTTGGGGCCCC\n+\nIIIIIIIIIIII\n' \
  | gzip > input/sample_B_R1.fastq.gz

printf '@sample_B_read_1/2\nCCCCGGGGTTTT\n+\nIIIIIIIIIIII\n@sample_B_read_2/2\nGGGGCCCCAAAA\n+\nIIIIIIIIIIII\n' \
  | gzip > input/sample_B_R2.fastq.gz

printf 'sample\tgroup\nsample_A\tcontrol\nsample_B\ttreatment\n' \
  > metadata/samples.tsv

printf 'Progetto creato in: %s\n' "$PWD"
ls -R

La struttura risultante è:

microbiome-bash-lab/
├── input/       # dati grezzi: non modificarli
├── metadata/    # informazioni sui campioni
├── output/      # risultati delle analisi
├── logs/        # registrazione dei comandi e dei messaggi
└── notes/       # appunti e copie di lavoro
ConsiglioBuona pratica

Conserva i dati originali in input/ e scrivi risultati e file temporanei altrove. Un workflow è più facile da controllare quando input e output non sono mescolati.

1. Terminale, shell e Bash

Il terminale è la finestra in cui scriviamo. La shell interpreta ciò che scriviamo. Bash è la shell usata in questa lezione.

Una riga del terminale può assomigliare a questa:

(metabarcoding-phd) nomeutente@computer:~/microbiome-bash-lab$

Le parti principali sono:

  • (metabarcoding-phd): ambiente Conda attivo;
  • nomeutente@computer: utente e computer;
  • ~/microbiome-bash-lab: directory corrente;
  • $: il terminale è pronto a ricevere un comando.

Il prompt è mostrato dal terminale: non va ricopiato.

Anatomia di un comando

La struttura più comune è:

comando [opzioni] [argomenti]

Esempio:

ls -lh input/
Parte Ruolo
ls comando: elenca il contenuto di una directory
-l opzione: usa un elenco dettagliato
-h opzione: mostra dimensioni leggibili, per esempio KB o MB
input/ argomento: la directory su cui deve lavorare ls

Gli spazi separano le parti del comando. Bash distingue maiuscole e minuscole: Input, input e INPUT sono tre nomi diversi.

Prova tre comandi semplici:

date
whoami
echo "Sto usando Bash"

Le righe che iniziano con # sono commenti e non vengono eseguite:

# Questo è un commento
echo "Questo invece viene eseguito"

Non serve memorizzare tutto

Molti programmi mostrano una guida con --help o -h:

ls --help | less

Scorri con le frecce e premi q per uscire. Per i comandi di sistema è spesso disponibile anche il manuale:

man ls

2. Dove sono? Che cosa c’è qui? Come mi sposto?

Tre comandi rispondono alle domande fondamentali:

Domanda Comando
Dove sono? pwd
Che cosa c’è qui? ls
Come mi sposto? cd

Torna all’inizio del progetto e osserva la directory:

cd "$HOME/microbiome-bash-lab"
pwd
ls
ls -lah
ls -lh input/

pwd significa print working directory. Dovrebbe mostrare un percorso che termina con:

/microbiome-bash-lab

Con ls -lah:

  • -l mostra dettagli;
  • -a include gli elementi nascosti, i cui nomi iniziano con .;
  • -h mostra dimensioni leggibili.

Percorsi assoluti e relativi

Un percorso è l’indirizzo di un file o di una directory.

Simbolo Significato
/ radice del filesystem
~ oppure $HOME home dell’utente corrente
. directory corrente
.. directory superiore

Un percorso assoluto parte da / o dalla home:

/home/nomeutente/microbiome-bash-lab/input/sample_A_R1.fastq.gz

Un percorso relativo parte dalla directory in cui ci troviamo:

input/sample_A_R1.fastq.gz

Il percorso relativo funziona soltanto quando la posizione corrente è quella prevista. Per questo pwd è uno dei migliori strumenti di controllo.

Esercizio guidato di navigazione

cd "$HOME/microbiome-bash-lab"
pwd

cd input
pwd
ls -lh

cd ..
pwd

cd metadata
pwd

cd -
pwd

cd - torna alla directory precedente. cd senza argomenti torna alla home:

cd
pwd

Ora torna al progetto usando il completamento con Tab: inizia a scrivere cd ~/micro e premi Tab.

cd "$HOME/microbiome-bash-lab"
ConsiglioAbitudine utile

Prima di lanciare un’analisi esegui sempre pwd e ls -lh. Molti errori derivano semplicemente dal trovarsi nella directory sbagliata.

3. Creare, copiare, spostare e rinominare

Creare directory con mkdir

Crea due sottodirectory per i risultati:

cd "$HOME/microbiome-bash-lab"
mkdir -p output/qc output/tables
ls -R output

L’opzione -p crea anche eventuali directory intermedie e non produce errore se la directory esiste già.

Copiare con cp

La forma generale è:

cp origine destinazione

Crea una copia dei metadata nella directory degli appunti:

cp -i metadata/samples.tsv notes/samples_copy.tsv
ls -lh notes/

-i significa interactive: se il file di destinazione esiste già, cp chiede conferma prima di sovrascriverlo.

Spostare o rinominare con mv

mv usa la stessa logica di origine e destinazione. Se origine e destinazione sono nella stessa directory, il file viene rinominato:

mv -i notes/samples_copy.tsv notes/samples_backup.tsv
ls -lh notes/

Per spostarlo in una directory mantenendo lo stesso nome, indica soltanto la directory come destinazione:

mv -i notes/samples_backup.tsv output/qc/
ls -lh output/qc/

Sicurezza: cancellare non equivale al cestino

Il comando rm cancella normalmente i file in modo permanente. Non è necessario usarlo in questa esercitazione.

AvvisoPrima di cancellare qualsiasi cosa

Controlla pwd, controlla ls, completa il nome con Tab e non usare sudo come tentativo generico di risolvere un errore. Evita soprattutto comandi ricorsivi copiati senza comprenderli.

Anche cp e mv possono sovrascrivere file. Durante l’apprendimento è prudente usare cp -i e mv -i.

4. Ispezionare file di testo e FASTQ compressi

In bioinformatica molti file sono troppo grandi per essere aperti interamente. Conviene prima osservarne una piccola parte.

File di testo

Il file metadata/samples.tsv è una tabella di testo separata da tabulazioni:

cd "$HOME/microbiome-bash-lab"
head -n 3 metadata/samples.tsv
tail -n 2 metadata/samples.tsv
wc -l metadata/samples.tsv
Comando Funzione
head -n 3 mostra le prime 3 righe
tail -n 2 mostra le ultime 2 righe
wc -l conta le righe

Per consultare un file in modo interattivo:

less metadata/samples.tsv

Dentro less:

  • usa le frecce o Page Up/Page Down per spostarti;
  • digita /sample_B e premi Invio per cercare;
  • premi n per andare all’occorrenza successiva;
  • premi q per uscire.

cat stampa tutto il contenuto di un file ed è adatto soltanto a file piccoli:

cat metadata/samples.tsv

Riconoscere i file compressi

file input/sample_A_R1.fastq.gz
ls -lh input/*.fastq.gz

Un file .fastq.gz è un FASTQ compresso con gzip. Non usare cat direttamente: vedresti dati compressi illeggibili.

gzip -cd decomprime verso il terminale senza modificare il file originale. Collegandolo a head, osserviamo soltanto le prime otto righe:

gzip -cd input/sample_A_R1.fastq.gz | head -n 8

Un record FASTQ occupa quattro righe:

@identificativo_della_lettura
SEQUENZA
+
QUALITA

Otto righe corrispondono quindi a due letture. Possiamo verificarlo così:

gzip -cd input/sample_A_R1.fastq.gz | wc -l

Nel piccolo file di esercizio il risultato è 8. Per file reali è preferibile usare un programma che comprenda direttamente il formato FASTQ, per esempio SeqKit:

conda activate metabarcoding-phd
seqkit stats input/*.fastq.gz

Controllo rapido delle coppie R1/R2

I file paired-end devono avere un file R1 e un file R2 per ciascun campione.

ls input/*_R1.fastq.gz
ls input/*_R2.fastq.gz

ls input/*_R1.fastq.gz | wc -l
ls input/*_R2.fastq.gz | wc -l

In questa esercitazione devono esserci due file R1 e due file R2.

NotaFile compressi e conteggio delle righe

wc -l file.fastq.gz non conta le letture: lavora sui dati binari compressi. Prima bisogna decomprimere verso lo standard output oppure usare un programma come SeqKit.

5. Wildcard, pipe, redirezioni e log

Questi operatori permettono di lavorare su molti file e di combinare comandi semplici.

Wildcard: selezionare più file

L’asterisco * rappresenta zero o più caratteri.

ls input/*.fastq.gz
ls input/sample_A_*
ls input/*_R1.fastq.gz

Interpretazione:

Espressione Seleziona
input/*.fastq.gz tutti i FASTQ compressi in input/
input/sample_A_* tutti i file il cui nome inizia con sample_A_
input/*_R1.fastq.gz tutti i file forward R1

Bash espande il wildcard prima di avviare il comando. Prima di usare un wildcard con comandi che modificano file, controlla sempre la selezione con ls.

Il punto interrogativo ? rappresenta esattamente un carattere. Nel nostro esempio:

ls input/sample_?_R1.fastq.gz

seleziona sample_A_R1.fastq.gz e sample_B_R1.fastq.gz.

Pipe: usare l’output di un comando come input del successivo

La pipe è il simbolo |:

comando_1 | comando_2

L’output di comando_1 non viene stampato direttamente: diventa l’input di comando_2.

Abbiamo già usato una pipe:

gzip -cd input/sample_A_R1.fastq.gz | head -n 8

Altri esempi:

ls input/*.fastq.gz | wc -l
seqkit stats input/*.fastq.gz | less

Il primo conta i file selezionati. Il secondo permette di consultare l’output di SeqKit con less.

Redirezione: scrivere l’output in un file

Il simbolo > salva l’output in un file invece di mostrarlo sul terminale:

ls input/*.fastq.gz > logs/input-files.txt
head logs/input-files.txt
AvvisoAttenzione alla sovrascrittura

> crea il file se non esiste, ma lo sovrascrive se esiste già.

Il simbolo >> aggiunge l’output in fondo a un file esistente:

date > logs/session.log
ls input/*.fastq.gz >> logs/session.log
cat logs/session.log

tee: mostrare e salvare nello stesso momento

tee copia l’output sia sul terminale sia in un file:

seqkit stats input/*.fastq.gz | tee logs/seqkit-stats.log

Molti programmi inviano alcuni messaggi su un secondo canale chiamato standard error. Per salvare in un unico log sia l’output normale sia i messaggi di errore:

seqkit stats input/*.fastq.gz 2>&1 | tee logs/seqkit-stats.log
  • 2>&1 unisce standard error e standard output;
  • | tee ... mostra tutto e ne salva una copia.

Questa è una struttura molto utile per i workflow:

comando_con_opzioni 2>&1 | tee logs/nome-analisi.log

Dopo l’esecuzione, controlla il log:

head logs/seqkit-stats.log
tail logs/seqkit-stats.log
ConsiglioPerché conservare i log?

I log permettono di ricostruire ciò che è successo, individuare errori e comunicare al docente o a un collaboratore l’esatto messaggio prodotto dal programma.

6. Ambiente Conda e help dei programmi

Un ambiente Conda mantiene insieme versioni compatibili dei programmi necessari per il corso.

Mostra gli ambienti disponibili:

conda env list

Attiva l’ambiente del corso:

conda activate metabarcoding-phd

Il nome dell’ambiente dovrebbe comparire all’inizio del prompt. Controlla il percorso dell’ambiente e il programma che verrà eseguito:

echo "$CONDA_PREFIX"
command -v seqkit
seqkit version

command -v risponde alla domanda: “quale eseguibile userà Bash quando scrivo questo nome?”. Il percorso dovrebbe trovarsi dentro l’ambiente metabarcoding-phd.

Per scoprire le opzioni di un programma:

seqkit stats --help | less

Per vedere gli ultimi comandi eseguiti:

history | tail -n 10

Per uscire dall’ambiente:

conda deactivate

Durante il corso, riattivalo prima di usare AmpWrap o gli altri programmi bioinformatici:

conda activate metabarcoding-phd

Routine di controllo prima di lanciare AmpWrap

Questa sequenza riduce molti errori comuni:

conda activate metabarcoding-phd
cd "$HOME/microbiome-bash-lab"

ls -lh input/

comando_ampwrap_con_le_opzioni 2>&1 | tee logs/ampwrap.log

Bash is not a list of commands to memorize. It is a precise and reproducible way to tell the computer where the data are, which program should use them, and where the results should go.

This lesson takes about 60 minutes and is designed for people who have never used a terminal before. We work on a small example project with compressed FASTQ files, organized like a real analysis.

By the end of the lesson, you should be able to:

  • recognize terminal, shell, prompt, command, option, and argument;
  • move around the filesystem with pwd, ls, and cd;
  • create and organize folders with mkdir, cp, and mv;
  • inspect text files and compressed FASTQ.gz files without opening them fully;
  • select multiple files with wildcards and connect commands with a pipe;
  • save output and error messages to a log file;
  • activate the course Conda environment and find program help.

1. Terminal, shell, and Bash

The terminal is the window where we type. The shell interprets what we type. Bash is the shell used in this lesson.

A terminal line can look like this:

(metabarcoding-phd) username@computer:~/microbiome-bash-lab$

The main parts are:

  • (metabarcoding-phd): active Conda environment;
  • username@computer: user and computer;
  • ~/microbiome-bash-lab: current directory;
  • $: the terminal is ready for a command.

The prompt is shown by the terminal: do not type it again.

Command anatomy

The most common structure is:

command [options] [arguments]

Example:

ls -lh input/
Part Role
ls command: list a directory
-l option: long listing
-h option: human-readable sizes
input/ argument: the directory to inspect

Spaces separate parts of the command. Bash is case-sensitive: Input, input, and INPUT are different names.

Try three simple commands:

date
whoami
echo "I am using Bash"

Lines starting with # are comments and are not executed:

# This is a comment
echo "This one is executed"

You do not need to memorize everything

Many programs show a guide with --help or -h:

ls --help | less

Scroll with the arrows and press q to exit. For system commands, a manual page is often available:

man ls

2. Where am I? What is here? How do I move?

Three commands answer the basic questions:

Question Command
Where am I? pwd
What is here? ls
How do I move? cd

Go back to the project root and inspect the directory:

cd "$HOME/microbiome-bash-lab"
pwd
ls
ls -lah
ls -lh input/

Absolute and relative paths

A path is the address of a file or directory.

Symbol Meaning
/ filesystem root
~ or $HOME your home directory
. current directory
.. parent directory

An absolute path starts from / or the home folder:

/home/username/microbiome-bash-lab/input/sample_A_R1.fastq.gz

A relative path starts from the current directory:

input/sample_A_R1.fastq.gz

Relative paths only work if you are in the expected directory. That is why pwd is such an important check.

cd "$HOME/microbiome-bash-lab"
pwd

pwd

pwd

pwd

Create, copy, move, and rename

Create a directory:

mkdir results
mkdir -p output/fastqc

Copy a file:

cp metadata/samples.tsv notes/samples_backup.tsv

Move or rename:

mv notes/samples_backup.tsv notes/samples_info.tsv

Safer versions ask for confirmation before overwriting:

cp -i metadata/samples.tsv notes/samples_info.tsv
mv -i notes/samples_info.tsv notes/samples.tsv

Inspect text and compressed FASTQ files

Look at the first lines of a text file:

head -n 5 metadata/samples.tsv

Count lines:

wc -l metadata/samples.tsv

Identify a file:

file input/sample_A_R1.fastq.gz

Read a compressed FASTQ without modifying it:

gzip -cd input/sample_A_R1.fastq.gz | head

Wildcards, pipes, redirection, and logs

Use wildcards to select multiple files:

ls input/*.fastq.gz

Pass the output of one command to the next:

gzip -cd input/sample_A_R1.fastq.gz | head -n 8

Write output to a file:

ls -lh input/ > logs/input_listing.txt

Show and save at the same time:

ls -lh input/ | tee logs/input_listing.txt

Conda and program help

conda activate metabarcoding-phd
command -v seqkit
seqkit --help | head

Quick command sheet

Command Use
pwd print the current directory
ls -lah list files, hidden items, and readable sizes
cd path move into a directory
cd .. go up one level
cd or cd ~ go back home
cd - return to the previous directory
mkdir -p path create a directory and missing parent folders
cp -i source dest copy and ask before overwriting
mv -i source dest move or rename and ask before overwriting
head -n N file show the first N lines
tail -n N file show the last N lines
less file inspect a file; exit with q
wc -l file count lines
file filename identify the file type
gzip -cd file.gz decompress to standard output without changing the original
* wildcard: zero or more characters
? wildcard: one character
command1 \| command2 send the first command’s output to the second
> write and overwrite a file
>> append to a file
2>&1 merge error and normal output
tee file.log show and save output
command -v program show which executable will be used
program --help display program help
Ctrl+C stop or cancel
Tab complete and verify names and paths

What we did not cover

In one hour it is not realistic to go deep into scripting, for loops, complex variables, grep, awk, sed, permissions, remote servers, and process management. Those topics become useful after navigation, paths, pipes, and logs are solid.
